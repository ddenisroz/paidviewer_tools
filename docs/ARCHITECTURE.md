# Architecture Overview

TTS_TTV follows a clean architecture split into API, services, repositories, and integrations.

## Layers
- API: FastAPI routes, WebSocket endpoints, auth.
- Services: business logic (TTS, YouTube queue, rewards, chat).
- Repositories: DB access and queries.
- Integrations: Twitch, VK Live, DonationAlerts, TTS providers.

## Core Flows
- Chat messages are ingested by bots and stored in the DB.
- TTS requests are generated by services and sent to the TTS service.
- YouTube requests are queued and controlled from the dashboard.
- VK Live chat polling connects to all active VK channels on startup.
- Google Cloud TTS uses per-user voice pools stored in `tts_user_settings.gcloud_voices`.

## Frontend Caching
- Query cache keys in localStorage use the `rq_cache_` prefix and are auto-pruned by age and count on app startup.
