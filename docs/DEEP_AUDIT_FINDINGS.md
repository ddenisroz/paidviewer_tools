## 📋 Обнаруженные проблемы

### 1. ✅ ИСПРАВЛЕНО: Дублирование запросов в PlayerContext

**Проблема:**
- `loadQueue()` вызывается в трех местах:
  1. `useInterval` каждые 15 секунд
  2. `useEffect` при монтировании
  3. `useEffect` при WebSocket сообщении `youtube_queue_update`

**Риск:** Дублирование запросов, избыточная нагрузка на сервер, возможные race conditions.

**Решение:** ✅ Добавлена защита от дублирования через `isLoadingQueueRef` ref. Периодические обновления проверяют флаг перед вызовом. При монтировании и WebSocket обновлениях используется `force = true` для немедленной загрузки.

**Файл:** `frontend/src/context/PlayerContext.jsx:129-177, 383-413`

---

### 2. ✅ ИСПРАВЛЕНО: Stale closures в DataContext

**Проблема:**
- `loadStreamData` и `loadStreamHistory` используются в `useEffect`, но не включены в зависимости
- Комментарий говорит "Убираем loadStreamData и loadStreamHistory из зависимостей", но это может привести к stale closures

**Риск:** Функции могут использовать устаревшие значения из замыкания.

**Решение:** ✅ Добавлены функции в зависимости `useEffect`. Добавлена защита от дублирования через `isLoadingHistoryRef` и `isLoadingStreamDataRef`. Функции правильно мемоизированы с `useCallback` и все зависимости включены.

**Файл:** `frontend/src/context/DataContext.jsx:268-404, 622-631`

---

### 3. ✅ ИСПРАВЛЕНО: Задержка загрузки истории чата

**Проблема:**
- Задержка 1.5 секунды перед загрузкой истории из API
- Пользователь видит пустой чат в течение 1.5 секунд

**Риск:** Плохой UX, пользователь думает что чат не работает.

**Решение:** ✅ Заменена фиксированная задержка на умную логику: проверка WebSocket подключения (`isConnected`) каждые 100ms, максимум 2 секунды. Если WebSocket подключен, дается еще 500ms для получения истории, затем загрузка из API. Это значительно улучшает UX.

**Файл:** `frontend/src/context/ChatContext.jsx:95-116, 163`

---

### 4. ✅ ИСПРАВЛЕНО: Не мемоизированные функции в YoutubeIntegrationPage

**Проблема:**
- `loadYoutubeSettings` и `loadExistingObsUrl` не обернуты в `useCallback`
- Вызываются в `useEffect` с пустым массивом зависимостей

**Риск:** Не критично, но может привести к проблемам если функции будут использоваться в других местах.

**Решение:** ✅ Обе функции обернуты в `useCallback` для консистентности и стабильности зависимостей. Добавлены в зависимости `useEffect`.

**Файл:** `frontend/src/pages/media/YoutubeIntegrationPage.jsx:61-163`

---

### 5. ✅ ИСПРАВЛЕНО: Дублирование состояния badges в ChatCard

**Проблема:**
- Используются одновременно `badgesLoadedRef.current` и `badgesLoaded` state
- Может привести к рассинхронизации

**Риск:** Badges могут загружаться дважды или не загружаться вообще.

**Решение:** ✅ Используется `badgesLoaded` state как источник истины для проверки условий загрузки. `badgesLoadedRef` используется только для защиты от дублирования (флаг начала загрузки). Добавлен cleanup для timeout.

**Файл:** `frontend/src/components/ChatCard.jsx:227-288`

---

### 6. ✅ ИСПРАВЛЕНО: Ручной кэш в CommandsPage вместо React Query

**Проблема:**
- Используется ручной кэш с `lastLoadTime` и `CACHE_TTL`
- Не интегрирован с React Query для автоматической синхронизации

**Риск:** Проблемы с синхронизацией между компонентами, дублирование логики кэширования.

**Решение:** ✅ Полностью переведено на React Query. Удален ручной кэш. Добавлены mutations для всех операций (создание, обновление, удаление, переключение). Используется optimistic updates для мгновенного UI. `basicTags` вычисляется через `useMemo` вместо state.

**Файл:** `frontend/src/pages/CommandsPage.jsx:89-194, 264-268, 313-382`

---

### 7. ✅ ИСПРАВЛЕНО: Зависимости в useInterval

**Проблема:**
- `useInterval` в `PlayerContext` вызывает `loadQueue`, которая зависит от `isAuthenticated`
- При изменении `isAuthenticated` интервал может не обновиться корректно

**Риск:** Интервал может продолжать работать после выхода пользователя.

**Решение:** ✅ Интервал правильно останавливается при `isAuthenticated === false` (delay = null). Добавлена проверка `!isLoadingQueueRef.current` перед вызовом `loadQueue` для предотвращения дублирования.

**Файл:** `frontend/src/context/PlayerContext.jsx:383-389`

---

### 8. ✅ ИСПРАВЛЕНО: Зависимости в DataContext useEffect

**Проблема:**
- `useEffect` использует `loadStreamData` и `loadStreamHistory`, но они не в зависимостях
- Функции обернуты в `useCallback`, но зависимости могут быть неполными

**Риск:** Stale closures, неправильное поведение при изменении зависимостей.

**Решение:** ✅ Функции добавлены в зависимости `useEffect`. Все зависимости `useCallback` проверены и корректны. Добавлена защита от дублирования через refs.

**Файл:** `frontend/src/context/DataContext.jsx:268-404, 622-639`

---

### 9. ✅ ИСПРАВЛЕНО: Утечки памяти в TtsHealthContext

**Проблема:**
- `setTimeout` создавались внутри `checkHealthRef.current`, но не очищались при раннем выходе или размонтировании компонента
- `timeoutPromise` создавал `setTimeout`, который не очищался если Promise.race завершался успешно
- Таймауты могли выполняться после размонтирования компонента

**Риск:** Утечки памяти, попытки обновить состояние размонтированного компонента, потенциальные ошибки.

**Решение:** ✅ Добавлен `timeoutsRef` для хранения всех активных таймаутов. Все таймауты очищаются в `finally` блоке и при размонтировании компонента. `healthCheckTimeoutId` очищается сразу после успешного завершения Promise.race.

**Файл:** `frontend/src/context/TtsHealthContext.jsx:39-207`

---

### 10. ✅ ИСПРАВЛЕНО: Бесконечный цикл в DonationSettings

**Проблема:**
- `useEffect` с зависимостями `[donationalertsConnected, formData.donation_enabled, formData.mythical_enabled]` изменял `formData`, что вызывало повторное выполнение эффекта

**Риск:** Бесконечный цикл обновлений, избыточные ре-рендеры, потенциальные проблемы с производительностью.

**Решение:** ✅ Использовано функциональное обновление `setFormData(prev => ...)` для чтения актуальных значений без добавления `formData` в зависимости. Эффект обновляет состояние только если значения действительно изменились (проверка `prev.donation_enabled || prev.mythical_enabled`). Удалены `formData.donation_enabled` и `formData.mythical_enabled` из зависимостей.

**Файл:** `frontend/src/components/drops/DonationSettings.jsx:90-108`
